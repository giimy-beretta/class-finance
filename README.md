# ระบบการเงินห้อง 5/2 (Flask + SQLite)

ผู้ชมทั่วไปดูข้อมูลได้อย่างเดียว ผู้เก็บเงิน 3 คน (ฉัตร, มีมี่, เพียว) ล็อกอินด้วยรหัสเพื่อ เพิ่ม/ลบ รายรับ-รายจ่าย,
เรียกเก็บเงินรายสัปดาห์ และบันทึกการรับเงินรายคน ทุกการแก้ไขถูกบันทึกใน Log ฝั่งเซิร์ฟเวอร์

## โครงสร้างไฟล์
```
class-finance/
├── app.py              # แอป Flask: หน้าเว็บ + API + ตรวจรหัส/CSRF/กันกดรัว/บันทึก Log
├── config.py           # ค่าตั้งค่า (อ่านจาก .env / environment)
├── db.py               # SQLite, ข้อมูลเริ่มต้น, อัปเกรดฐานข้อมูลอัตโนมัติ, คำสั่ง flask init-db / set-token
├── evidence.py         # ตรวจชนิดไฟล์หลักฐานจากเนื้อไฟล์ + ตั้งชื่อไฟล์บนดิสก์แบบสุ่ม
├── schema.sql          # โครงสร้างตาราง
├── tests/              # pytest (รันใน GitHub Actions ทุกครั้งที่ push)
├── Dockerfile · Procfile · render.yaml   # สำหรับ deploy
├── .github/workflows/ci.yml · .devcontainer/   # CI และ GitHub Codespaces
├── templates/index.html · static/style.css · static/script.js
└── instance/           # สร้างอัตโนมัติ เก็บ finance.db (ไม่ถูก commit — สำรองเป็นประจำ)
```

## การรับเงินนักเรียน (แก้บัคแล้ว)
กด "รับเงิน" ในแท็บนักเรียน → ในคำสั่งเดียวกัน ระบบจะ (1) ลดยอดค้างของคนนั้น (2) เพิ่ม **รายรับ** หมวด "รายได้รายอาทิตย์" ในประวัติรายการ/ภาพรวม/รายงานรายเดือน (3) เขียน Log
ถ้ากรอกผิดให้ลบที่ "ประวัติการเรียกเก็บ/รับเงิน" ระบบจะยกเลิกรายรับที่ผูกกันให้ด้วย (ลบรายรับนั้นตรง ๆ ไม่ได้ เพื่อไม่ให้ยอดไม่ตรงกัน)
ฐานข้อมูลเก่าที่เคยรับเงินไปแล้วแต่ไม่เข้ารายรับ จะถูกอัปเกรดและสร้างรายรับย้อนหลังให้ **ครั้งเดียว** อัตโนมัติตอนเริ่มระบบ (มีบันทึกใน Log)

## เริ่มใช้งานบนเครื่อง / GitHub Codespaces
```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env        # แก้ SECRET_KEY และ COLLECTOR_TOKENS
flask --app app run --debug # เปิด http://127.0.0.1:5000  (ฐานข้อมูลสร้างให้เองครั้งแรก)
```
Codespaces: กด Code → Codespaces → Create — ไฟล์ `.devcontainer` ติดตั้งและสร้าง `.env` ชั่วคราวให้ แล้วรัน `flask --app app run --debug`
เปลี่ยนรหัสภายหลัง: `flask --app app set-token ฉัตร` (ยาวอย่างน้อย 8 ตัวอักษร)

## ทดสอบ
```bash
pip install -r requirements.txt -r requirements-dev.txt
python -m pytest -q     # 74 เทสต์: ตรรกะการเงิน, หลักฐาน, ความปลอดภัยของ API, CSP, ความสอดคล้องของ id/ตัวแปรสีในหน้าเว็บ
```
- `tests/test_hardening.py`: จำนวนเงินต่ำกว่าสตางค์ (เดิมทำให้เกิด 500), เลขที่นักเรียน/วันที่ผิดรูปแบบ, ข้อผิดพลาด API เป็น JSON, CSP ของหน้าเว็บ, การจำกัดการเดารหัส
- `tests/test_frontend_contract.py`: ทุก `$("id")` ในสคริปต์ต้องมีใน HTML และไม่มี inline script/style

## ความปลอดภัยของหน้าเว็บ
- หน้าเว็บส่ง `Content-Security-Policy` ที่ไม่อนุญาตสคริปต์/สไตล์ inline — ห้ามเพิ่ม `onclick=` หรือ `style=` ใน HTML/JS (เทสต์จะล้มเหลวถ้าทำ)
- ข้อผิดพลาดของ `/api/*` ตอบเป็น JSON เสมอ และข้อผิดพลาดภายในไม่ถูกส่งให้ผู้ใช้ (รายละเอียดอยู่ใน log ของเซิร์ฟเวอร์)

## Deploy ใช้งานจริง
GitHub เก็บโค้ดและรัน CI/Codespaces ได้ แต่ **GitHub Pages รันแอป Flask ไม่ได้** ต้องมีที่รันเซิร์ฟเวอร์ (Render, Fly.io, Railway, VPS ฯลฯ) ที่ต่อกับ repo นี้
ตัวอย่าง Render: push repo ขึ้น GitHub → New > Blueprint → เลือก repo (ใช้ `render.yaml`) → กรอก `COLLECTOR_TOKENS` → Deploy
สิ่งที่ต้องมีเสมอ:
- `SECRET_KEY` คงที่ (ไม่ตั้ง = ระบบไม่ยอมเริ่ม) และ `SESSION_COOKIE_SECURE=1` เมื่อใช้ HTTPS
- ที่เก็บถาวร (disk/volume) สำหรับ `finance.db` ตั้ง `DATABASE_PATH` ชี้ไปที่นั่น (Docker image ใช้ `/data/finance.db`)
- `COLLECTOR_TOKENS` ตอนสร้างฐานข้อมูลครั้งแรก — ระบบ **ไม่ยอมเริ่ม** ถ้ายังมีรหัสเริ่มต้น `token-1..3`
- `TRUSTED_PROXIES=1` เมื่ออยู่หลัง proxy ของแพลตฟอร์ม เพื่อให้จำกัดการเดารหัสต่อ IP ใช้ IP จริง
- คำสั่งรัน: `gunicorn --preload -w 2 -b 0.0.0.0:$PORT app:app` (ดู `Procfile`) · health check: `/healthz`
- ย้ายข้อมูลเดิม: คัดลอกไฟล์ `finance.db` ไปไว้ที่ `DATABASE_PATH` (ระบบอัปเกรดให้เอง) แล้วตั้งรหัสใหม่ด้วย `flask --app app set-token`

## หลักฐานการจ่ายเงิน
- แนบรูปหรือ PDF ให้ **รายจ่าย** ได้ที่แท็บ "ประวัติรายการ" (ปุ่ม 📎 แนบหลักฐาน) รองรับ JPG, PNG, WEBP, GIF, PDF ไม่เกิน 5 MB ต่อไฟล์ และไม่เกิน 5 ไฟล์ต่อรายการ
- ระบบตรวจชนิดไฟล์จาก **เนื้อไฟล์จริง** ไม่ใช่จากนามสกุล ไฟล์ปลอมที่ตั้งชื่อ .png จะถูกปฏิเสธ
- ไฟล์เก็บใน `EVIDENCE_DIR` ซึ่งค่าเริ่มต้นอยู่ข้างไฟล์ฐานข้อมูล (local = `instance/evidence`, Docker/Render = `/data/evidence`)
- หลักฐานทุกไฟล์เปิดดูได้ที่หน้าเว็บ (ตามที่ข้อมูลอื่นเป็น) ถ้ามีข้อมูลส่วนตัว เช่น ที่อยู่หรือเบอร์โทรในใบเสร็จ ควรจำกัดให้เห็นเฉพาะผู้เก็บเงิน
- การลบหลักฐานเป็นการซ่อน ไฟล์ยังอยู่บนดิสก์ และทุกการแนบ/ลบอยู่ใน Log

## หมายเหตุ
- ยอดค้างชำระ = เรียกเก็บรวมทุกครั้ง − ยอดที่คนนั้นจ่าย (ไม่มีปุ่มรีเซ็ต; ลบได้เฉพาะรายการที่กรอกผิดทีละรายการ และทุกการลบอยู่ใน Log)
- อีเมลใน Log เป็นค่าที่ผู้เก็บเงินกรอกตอนล็อกอิน ระบบไม่ได้ยืนยันความเป็นเจ้าของ และผู้ชมทั่วไปไม่เห็นคอลัมน์นี้
- สำรองไฟล์ `finance.db` **และโฟลเดอร์ `evidence/`** เป็นประจำ (ไฟล์ใบเสร็จไม่ได้อยู่ในไฟล์ฐานข้อมูล)
